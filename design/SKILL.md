# Трудозатраты для PMP KIT (OpenProject)

Цель: превратить свободное описание работы в готовую запись для формы
«Добавить трудозатраты» на `pmp.kit.tj`.

Поля формы платформы: **Дата**, **Часы**, **Деятельность**, **Комментарий**.

## Шаг 1. Уточняющие вопросы

Если в запросе пользователя не хватает данных, задай недостающие вопросы —
**одним блоком, а не по одному**. Не задавай вопрос, если ответ уже есть
в сообщении пользователя или очевиден из контекста беседы.

1. **Период** — за какой день (или диапазон дней) списываем время?
   Если пользователь говорит «за сегодня» — использовать текущую дату.
   Формат даты в платформе: `ГГГГ-ММ-ДД`.

2. **Часы** — сколько времени затрачено?
   Если пользователь описал работу, но не назвал часы — спросить.
   Никогда не выдумывать и не оценивать часы самостоятельно.

3. **Язык отчёта** — русский или английский?
   По умолчанию русский, если пользователь пишет по-русски.

4. **Объём описания** — нужны оба описания (краткое + детальное)
   или только краткое?

5. **Вид деятельности** — если не указан, предложить из типовых:
   Разработка, Анализ, Тестирование, Документация, Совещание,
   Согласование, Управление проектом.

### Про восстановление работ из беседы

Скилл **не имеет доступа к истории прошлых чатов** и не может сам
«вытащить» что делалось по времени. Если пользователь просит собрать
отчёт по проделанной работе:

- использовать то, что обсуждалось **в текущей беседе**;
- если контекста в текущей беседе нет — честно сказать об этом
  и попросить перечислить задачи списком;
- не додумывать работы, которых пользователь не называл.

## Шаг 2. Формирование записи

### Правила текста

- Формулировки безличные, от результата: «Реализована классификация ошибок»,
  а не «я сделал классификацию».
- Без канцелярской воды: не писать «проведена работа по», «осуществлено
  выполнение мероприятий».
- Технические термины не переводить: middleware, pull request, миграция,
  API, деплой.
- Краткое описание — одна строка, до ~80 символов, без точки в конце.
- Детальное описание — 2–5 предложений: что конкретно сделано и какой
  получен результат. Без перечисления очевидных шагов.
- Часы — в формате платформы: `2h`, `1.5h`, `30m`.

## Шаг 3. Формат вывода

```
Дата: 2026-07-22
Часы: 2h
Деятельность: Разработка

Комментарий:
<краткое описание>

<детальное описание — если запрошено>
```

Если записей несколько (за период или по нескольким задачам) — выдать
списком, каждую в том же формате, и в конце подбить **итого часов**.

Если пользователь просил только краткое описание — блок детального
не выводить вообще.

## Замечания

- Не предлагать пользователю списать больше часов, чем он назвал.
- Если пользователь называет номер пакета работ (например `#1766`) —
  указать его в начале краткого описания.
- Если период охватывает несколько дней, а часы названы общей суммой —
  спросить, разбивать ли по дням или оформить одной записью.
